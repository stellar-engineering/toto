How this site is built

This site is two plain HTML pages, one stylesheet and one script, served by the same Cloudflare Worker as the relay. There is no build step, no framework and no package to install. What is in site/ is what you are reading.

This is for someone changing the site. What Toto is, and how to use it, is in the documentation.

What is in it

FileWhat it is
index.htmlThe home page: what Toto is, the live count, the download, four steps to get going.
docs.htmlThe documentation, as one page of sections with a contents list down the side.
architecture.htmlThis page.
toto.cssAll of the styling, for every page.
toto.jsEverything that moves or asks for data. One file, no imports, loaded at the end of each page.

The pages are served at /, /docs and /architecture. The .html is not part of the address.

How it is served

browser ──► toto.royletron.dev ──► Cloudflare Worker
                                     │
                                     ├─ a file in site/ ........ served as it is
                                     ├─ /stats .................. how many Totos are online
                                     ├─ /release ................ the latest release, from GitHub
                                     ├─ /announce (POST) ........ release workflow only
                                     └─ /v1/<id> (WebSocket) .... the relay itself

The Worker's configuration points its assets at the site folder. A request that matches a file there is answered without running any code. Only /v1/*, /stats, /announce and /release are listed under run_worker_first, so those reach the Worker and everything else is a file or a 404. A new route for a page to call has to be added to that list as well as to the Worker.

The site and the relay are one thing to deploy. npx wrangler deploy from relay/ publishes both.

What it asks for

The site is static, apart from two small questions it puts to the Worker.

Used forRouteAnswerKept for
The live count on the home page/statsThe number online, from a Durable Object that holds opaque device ids and the time each was last heard of. A device counts for 30 minutes after it was last heard from.The page asks every 15 seconds. The answer may be cached for 10.
The download button and the Android link/releaseThe latest version, and the image and the Android app if they are in the release yet. The Worker reads GitHub's release files because a page cannot ask GitHub directly.5 minutes

Both fail quietly. If /release does not answer, the button keeps its plain text and links to the releases page on GitHub. If /stats does not answer, the count says so and the mark goes to its offline face. Neither is a reason for a page to look broken.

The download button links straight to GitHub. The Worker never serves a release.

The script

toto.js is four independent pieces. Each does nothing if the element it works on is not on the page, which is how one file serves every page.

  • The mark. Any element with data-face is drawn as text and moved by swapping its characters. See Branding.
  • The contents list. Open down the side on a screen wider than 900px and folded into a menu on a narrower one. It marks the section being read: a section counts as read while its heading is in the top third of the screen.
  • The release. Fills in the version and the image's size on the button, and the Android link.
  • The live count. Asks /stats and sets the mark's mood: awake when any Toto is online, resting when none is, offline when the relay did not answer.

The landscape behind the page is drawn in the same file.

Branding

The site is the same world as the app: an unlit screen, one monospace face, amber for whatever is yours or is waiting on you. Dark only, and terminal-styled. Change any of it in the stylesheet and the app's theme together.

Colour

Each is a custom property at the top of toto.css. Use the name, not the value.

NameValueUsed for

--bezel#1d2119Raised surfaces: code blocks, the status line, the contents list on a narrow screen.
--rule#30362aEvery line and border.
--phosphor#ece6d2Text.
--ghost#959b85Secondary text, and things that are off.
--amber#ffb000What is yours, or waiting on you: the one thing to act on, the ❯ marker, code, the underscore in the name.
--signal#8bd45fAn agent at work, a healthy link. Not used on the site yet.
--raspberry#f25c82Errors, deny, delete. Not used on the site yet.
--sky#7fc8e8Links, and nothing else.

Amber is scarce on purpose. If a page has more than one or two places in amber, one of them is wrong. The landscape uses its own muted greens, which sit just above the page and are never brighter than the secondary text.

Type

One face: IBM Plex Mono, weights 400, 500 and 700, from Google Fonts, falling back to the system monospace. There is no second family. Body is 15px on a 1.6 line height; headings are bold, tight and balanced. Hierarchy comes from weight, size and the secondary colour, not from colour alone.

Layout

One left-aligned column, set like a terminal session, at most 1000px wide. Text is held to 64 characters a line. Sections are separated by a rule and space, not by boxes. Documentation pages add a 200px list of sections beside a 760px column.

The mark

A dog's face in six characters, /o o\ over a bullet nose. It is text, not an image, and it moves by swapping characters rather than by animating anything.

  • It has a mood per state. Awake blinks and glances. Resting closes its eyes and sleeps. Looking glances about, and is what the live count shows until the relay answers. Offline is still, in the secondary colour. Looking and offline have no nose. Waiting is amber.
  • Give it a role="img" and an aria-label that describes it, or aria-hidden="true" when it sits beside text that says the same thing.
  • The frames are in toto.js and match the app and the device's own console. Change one and change all three.

The name is written toto_, lower case, with the underscore in amber. It is a cursor. In running text the product is "Toto", and "a Toto" is one device.

Voice

  • Plain and specific. Say what happens, to whom, and what it costs. "Nothing is installed until you tap Update", not "seamless updates".
  • Honest about being early. Where something is missing or unproven the page says so, and the known limits are listed, not buried.
  • Second person, present tense. You and your Toto, your phone, your house.
  • No hype and no em dashes. Commas, colons and full stops.
  • Buttons and menu items are named as the app names them, in bold: Find a new Toto nearby, Sign in with Claude.
  • Use a non-breaking hyphen in "Wi‑Fi" so it does not split across a line.

The landscape

Three ridges of hills drawn in characters on a fixed canvas behind the page, drifting past at different speeds under a few stars. Each ridge is a sum of sines with random phases, so every visit has its own. It is decoration, and it stays that way: hidden from assistive technology, unable to take a click, behind everything, drawn only once the font has loaded, stopped while the tab is hidden, and still when the visitor has asked for reduced motion. The mark is still then as well.

Accessibility

  • Text is the text colour or the secondary colour on the page or a raised surface. Keep to those pairings, and check any new one.
  • Every section has a heading with an id, and its section is labelled by it.
  • Focus is shown as a 2px amber outline.
  • Pictures made of text, such as the mark and the app's conversation on the home page, are marked as images with a description of what they show.
  • The live count is in a polite live region.
  • The contents list is a details element, so it works as a menu with no script, and with script it follows the screen's width.
  • Motion is off under prefers-reduced-motion.

Changing it

Add a documentation section
Add a section labelled by an h2 with an id, and a link to it in the contents list. The script marks the section being read from the headings' ids, so nothing else is needed.
Add a page
Add site/<name>.html with the same head, header and footer as this one and link it from the header. It is served at /<name>. For a contents list, copy this page's structure: .with-side and .doc are what the script and stylesheet look for.
Add something that asks the Worker
Add the route to the Worker and to run_worker_first, give the answer a cache-control so every visitor does not reach it, and make the page work when it does not answer.
Change the colours or the face
Do it in :root in toto.css, then in the app's theme.ts, so the two stay one world.
Try it
There is nothing to build. Run npm run dev in relay/ to serve the site and the Worker together on localhost:8787. Opening the files directly works for the layout, but the count and the download will not answer.

Known limits

  • The font comes from Google Fonts. A visitor's browser asks Google for it. Serving it from the site itself would remove that, and is not done yet.
  • No light theme. The site is dark only, as the app is.
  • The landscape redraws a canvas every 220ms. It is cheap, but not free on a very old phone. Reduced motion turns it off, and there is no other switch.
  • One script for every page. Fine while it is small. If it grows a piece only one page needs, split it.
  • The site and the relay deploy together. A mistake in one blocks the other, and they share an address. The relay has no usage limits yet.
